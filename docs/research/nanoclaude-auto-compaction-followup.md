## Evidence boundaries

- The authenticated **interactive** `claude` TTY trace from 2026-09-28 is in [nanoclaude-interactive-tty.md](nanoclaude-interactive-tty.md) with sanitized structural JSONL. It proves the observed **manual** `/compact` wire and tool call/result packaging, **not** an automatic interactive trigger.
- For a new automatic-trigger trial we installed the same 2.1.284 release on a second authorized macOS Hand, launched actual interactive `claude` in tmux under a process-local TLS relay, and sent a synthetic two-Read prompt. That Hand's preexisting Max CLI login returned `/api/oauth/profile` 401 and five `/v1/messages` 401 attempts: `OAuth access token is invalid`. `claude auth status` had reported `loggedIn: true`, but this was stale local state. There was **no successful response and no automatic compaction measurement** in this trial. We stopped tmux/relay and removed the temporary CA/private keys; no credential/header values or prompt bodies were saved. The previously authenticated Mac Hand was offline at this time. Do not substitute a `-p` experiment for an interactive measurement.
- The following threshold/control-flow observations are from **read-only inspection of the installed 2.1.284 CLI executable's bundled JavaScript**, not live observations. Identifiers below are local minifier labels, not a stable public API.

## Auto-compaction source path (provisional until interactive validation)

1. `zC` resolves an effective window, capped by the model context window. The inspected precedence is `CLAUDE_CODE_AUTO_COMPACT_WINDOW` > setting > client-data override > experiment > model/default. It reports the chosen source. The configured value must pass bounds validation. This is not equivalent to setting the model's actual context length.
2. `kK` subtracts the **model output capacity**, capped at 20,000 tokens, from that window. `_Q` normally subtracts a further 13,000-token margin; a test-only percent override can lower the trigger. For a 100,000-token window and a current model with >=20,000 output capacity, the nominal compact threshold is **67,000** estimated tokens. `dTe` additionally distinguishes `ok`, `warn`, `compact`, and `blocked`; it is not just one unconditional token comparison.
3. `Vpo` tests feature/eligibility guards and estimates the packed messages (with server-cleared-token adjustment) before declaring compact/blocked. `hvr` checks `DISABLE_COMPACT`, a failure breaker, fixed-prefix overflow and rapid-refill protection, then routes configured windows through a reactive path or invokes a direct auto-summary path. These feature gates mean 67,000 is a **source-derived nominal threshold, not an empirically measured onset** in the authenticated TTY.
4. The direct summary path calls `K$n` with `isAutoCompact:true`, which invokes hooks, builds a compaction prompt, sends a separate Messages summarization through `xCt`, validates the text response, records a boundary/discovered-tool metadata, then rebuilds a continuation message via `Pq`. The configured-window reactive branch can instead call `U$n`, including a precomputed swap/last-resort branch. Therefore neither the request timing nor packing of the automatic branch can be asserted from the one manual `/compact` trace alone.
5. The observed manual request in the previous trace was class `compaction`, a separate streamed Messages request with the current tool catalog and full prior history plus two final user text blocks (1,414 and 6,361 characters). It did **not** use the separate Anthropic server `compact_20260112` edit or new on-demand signed `compaction` API. Those official APIs are valid but not interchangeable with the observed CLI harness protocol.

## Changes in draft Nanoclaude backend

- The harness now accepts a separately configured auto-compaction window and reserves 20k model-output tokens + 13k headroom for current coding models, rather than subtracting the *request* `max_tokens`. A synthetic 100k-window test checks the 67k boundary. This remains provisional because the live interactive auto trigger is unmeasured.
- A tool-heavy turn can compact **between provider calls inside one turn** after checkpointing the completed assistant/tool-result pair. Its summary continuation does not rerun the side effect. A large-result test covers this path; new result bytes are conservatively estimated at four bytes/token. This is a safe implementation choice, not a claim of exact CLI estimator parity.
- Both sequential and opt-in parallel client-tool execution retain completed results on cancellation and place explicit `is_error:true` **outcome-unknown** results for interrupted calls. All tool-use IDs stay paired and ordered in one user message on the next turn; the already-completed operation is not re-executed by the harness. This is an **in-process** checkpoint, not durable effect idempotency after a crash. Tests cover A-completes/B-blocks/cancel in both modes.
- `pause_turn` server-tool blocks are checkpointed before continuation so a failed next request does not drop opaque server-tool history. A failure/recovery test covers replay without fabricated client `tool_result`.
- Client ToolSearch now returns both `tool_reference` and a short neutral companion text block, matching the previously observed structure without copying private wording.

## Still not exact

The current summary instruction is a generic one-block request, and continuation is a single user message, versus the **observed manual** two-block instruction and five-message continuation. First-party system-role messages and private Claude Code prompts are not copied to a third-party API without an explicit supported contract. Automatic interactive trigger, reactive/precompute branch selection, and actual result ordering on a freshly logged-in subscription remain unverified. OAuth integration for Nanoclaude itself is also not implemented or validated; an existing CLI login is not permission to impersonate the CLI.

Official API references (different feature family): [threshold compaction](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold), [on-demand compaction](https://platform.claude.com/docs/en/build-with-claude/compaction-on-demand).
